# Agent Note: Client task dashboard

Status: implemented

[English](2026-08-17-client-task-dashboard.md) | 中文

## Problem

Web 客户端通过彼此独立的控件呈现 Session 状态、目标、计划模式、子代理、后台任务、工具执行、待处理交互和排队输入。用户可以检查每项事实，但右栏工作区首页此前只有导航磁贴，因此跟进任务需要在对话标题栏、输入区、侧栏和 Trajectory 之间切换。

产品缺少一个紧凑的当前任务摘要。该视图不能引入另一套任务状态模型，也不能推断现有记录无法证明的结果。

## Decision

`details.home` 占用方作为任务概览。它通过框架标准钩子读取当前 `ConversationSnapshot`、Session 列表镜像以及现有 `goal` 和 `plan` 投影。它不发起 RPC，不追加 Session 事件，也不拥有业务状态。

状态行使用封闭的优先级：已移除 Session、可回答交互、错误、运行中的轮次、排队输入，最后是就绪。即使 Agent 仍报告正在运行，这一顺序也会优先显示需要用户处理的操作。任务概览显示首个可用的 Agent、prompt 或打开错误，不再自行分类。

四项指标分别报告子代理后代、活动后台任务、正在运行的根工具调用和排队输入。子代理总数使用运行时中能识别普通 fork 截断的谱系索引。任务只统计 `running` 和 `stopping`；已结算任务仍可从现有标题栏列表查看。工具行使用当前进行中的调用投影，活动行保持有界，避免狭窄详情栏变成第二份对话记录。

Goal 区块呈现持久目标、阶段和已接纳轮次数。Plan 标记呈现折叠后的有效目标（`pending ? !active : active`）。能力缺失时省略相应区块，不显示不可用占位符。

Changes、File 和 Browser 继续作为摘要下方的工作区操作。切换 Session 时，右栏通过现有布局行为返回该任务概览。

同一个 layout 所有者还提供三个根级浮层。任务中心为每个非空白、非子代理 Session 派生一行，并按以下优先级分类：待处理交互、失败的后台任务、正在运行的 Session 或活动任务，最后是已完成。通知收件箱把这些行过滤为现有的完成边沿、待处理交互和失败任务。选择任一行都会调用现有 Session 打开操作；两个浮层都不持久化已读状态，也不引入另一条状态记录。

`LayoutController` 还拥有可释放的应用命令注册表。Layout 贡献任务中心、通知、更改、File、快速打开文件和 Browser 命令；Settings 贡献设置与插件命令。`Ctrl+K` 打开命令面板，`Ctrl+P` 调用快速打开文件。贡献项使用跟随语言环境的标签函数，因此切换语言不需要重新注册。

快速打开文件通过现有 `fs.listDir` RPC 建立有界递归文件名索引，并排除 `.git` 和 `node_modules`。排序依次优先文件名前缀、文件名子串、路径子串和子序列。Layout store 保存八个最近打开的工作区相对路径，预览则提供面包屑和路径复制。这些都是框架本地的查看记录，而不是 Session 事件。

Changes 列表通过现有逐文件 `git.diff` RPC 获取增删行总数，并从 `git.status` 读取文件数和上游距离。它把可见变更顺序传给 SCM 详情，用于前后导航。全部暂存、全部取消暂存和提交继续使用现有 Git API；提交成功后显示缩写提交 id。

Electron preload 桥额外暴露一个 `notify` 调用。主进程先校验并限制 renderer 字符串，再构造 Electron `Notification`；点击通知会显示并聚焦工作台窗口。Renderer 只在建立初始 Session 列表基线后检测“无待处理到有待处理”和“未完成到完成”的转换，因此应用启动不会重放旧通知。

## Alternatives considered

**在 Host 增加任务聚合。** 未采用，因为每项显示事实都已经有权威客户端投影。Host 聚合会复制排序和新鲜度规则，并让 UI 变更修改产品协议。

**创建独立的任务概览包和 slot。** 未采用，因为 `details.home` 已经拥有完全相同的位置和导航生命周期。第二个占用方会为同一首页责任增加一套视图选择状态。

**呈现完整历史活动。** 未采用，因为 Chat 和 Trajectory 拥有持久历史。在任务概览中复制历史需要分页、事件解释和另一套导航模型，因此任务概览只显示实时工作。

**为任务分组、通知已读状态、文件搜索或 Git 摘要增加 Host RPC。** 未采用，因为每个请求视图都能从现有客户端投影和特权 API 计算得到。新的 Host 记录会复制 Session 生命周期事实，并为纯展示行为扩大协议。

## Consequences

打开右栏即可查看任务的当前协作状态和工作区操作，而不会改变模型输入、持久化或 Host 行为。状态与指标使用专用控件所依赖的同一组推送式 store 更新。

任务概览无法在现有运行状态之外区分子代理完成、失败和取消，也不会保留已结算活动。这些限制来自源投影的可见属性，而不是任务概览自行提供的回退推断。

全局“失败”分组反映失败的后台任务，因为 `SessionSummary` 没有休眠 Session 的错误字段。打开 Session 后仍可从完整对话错误投影查看错误。快速文件扫描限制为 5,000 个文件，并按需重建，而不是由文件监视器持续维护。原生通知只在 Electron 桥和操作系统通知能力可用时存在；Web 行为保持不变。
